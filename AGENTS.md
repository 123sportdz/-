# elhadath-reels project guide

- This is the complete reel-generation application: `reel.py`, `dashboard.py`, `reelbot.py`, `reelkit/`, publishing integrations, and the restricted Zo companion/browser bridge. Read `README.md` and `QUICKSTART.md` before broad changes.
- Supported Python is 3.11–3.13; follow the platform-specific setup in `QUICKSTART.md`. Run bridge tests with `python -m pytest -q`; the media/render regression suite is `python selftest.py` and requires the full media dependencies plus FFmpeg.
- Preserve the existing render, dashboard, Telegram bot, and publishing behaviors when changing shared code. Add regression coverage for bug fixes.
- Rights-sensitive publishing defaults: preserve source marks; remove only marks the user owns or is authorized to remove. YouTube uploads default to private and must fail closed when an expected channel cannot be verified. Production notes record facts only; they do not establish a license or legal defense.
- Never commit or expose API tokens, OAuth credentials, private videos, or relay state. Keep the browser bridge localhost-only, explicitly consented, and restricted to its allowlisted actions. Do not initiate publishing or external sends without a direct request.
- Keep the two Zo workflows separate: `tools.browser_bridge` serves an explicitly consented isolated Chromium tab; `zo_companion.py` handles separately paired, allowlisted diagnostics and approved source operations. Neither is a general remote shell or desktop.
- `web/` holds an independent React prototype UI (Vite + TS, localStorage only). It is not wired to `reel.py`/`dashboard.py` and its `RightsGateModal` is display-only; any future integration must route every publish through the `reelkit.rights` server gates. Do not add hardcoded API keys there.
- The reel-content studio lives in `creative_studio.html` and `reelkit/writer.py`; it must create football-reel copy, not become a general writing app. Selected clips must be completed jobs whose output resolves inside `outputs/`; send only three sampled still frames plus prompt text to Gemini, never the full video. Drafts stay local, and nothing is published automatically. Never return API keys; cover engine, path validation, and draft-store changes in `tests/test_writer.py`.
- The dashboard voice studio validates settings through `reelkit.voice.normalize_controls`; keep dashboard controls, `reel.py` and `autopilot.py` flags, and renderer options aligned. AI commentary length is an 8–80-word maximum (default 22); keep its prompt limit, post-generation cap, UI, and CLI values consistent. The creative studio script lengths are capped at 22/40/65 words. Manual scripts are not altered by these caps. Voice previews send text only, store preferences in browser local storage, and must never upload the source video. Energy/style guide text and Gemini TTS; Edge controls are voice, rate, and pitch. Cover the path in `tests/test_voice_controls.py`, `tests/test_writer.py`, `tests/test_visual_defaults.py`, and `tests/test_dashboard_ui.py`.
- The pre-render scout review uses short-lived in-memory sessions. Keep source paths and captions out of public responses; validate render sources against a ready session and `outputs/`. Generate only candidate still thumbnails locally; never expose or upload the source video through the review API. Manual trim windows must include the detected peak, remain within the source duration, last at least 3 seconds, and not exceed the configured reel maximum. Use the same validated window for preview and render, revalidate on the server, and batch at most ten candidates. Cover these rules in `tests/test_scout_review.py`.
- In v1.62, the professional default is one action-focused vertical crop, with source marks preserved, tracker overlays hidden, and a compact top-right channel badge. Keep dashboard options aligned with `reel.py` CLI choices and cover defaults in `tests/test_visual_defaults.py`.
- In v1.63, use `quantize=16` with Ultralytics 8.4+ (legacy `half` only before 8.4), release detector references and CUDA cache before video encoding, and retry NVENC memory/device failures with libx264; cover this in `tests/test_encoder_resilience.py`.
- In v1.64, `add_replay` retries NVENC failures with libx264 (same failover policy as the main render), and `reel.py` prints a `reelkit.quality.check` report after every render. Cover replay failover in `tests/test_encoder_resilience.py`.
- In v1.65, `selftest.py` includes `unit_replay_failover` so the on-device self-test verifies replay NVENC→libx264 failover without pytest, and `doctor.py`'s NVENC line mentions the automatic CPU fallback.
- Publish-path errors use `reelkit.errors.friendly_error` (Arabic, no raw exception text) for clients and `reelkit.errors.error_detail` for server-side logs only; `reelkit.audit.append_event` records publish/status events in `outputs/audit/events.jsonl`. Never return raw provider exception text (tokens, paths) in HTTP responses; cover in `tests/test_audit.py` and `tests/test_youtube_dashboard.py`.
- Channel-name visibility applies only to the user's own badge; its URL/logo and all source marks remain unchanged. Do not add scoreboard/time/team-name blurring to evade copyright matching—use footage the channel owns or is licensed to publish. Cover visibility defaults, persistence, and CLI arguments in `tests/test_dashboard_ui.py` and `tests/test_visual_defaults.py`.
- Channel identity visibility (`show_channel_name` / `--hide-channel-name`) affects only the user's added badge name; keep their URL/logo separate and preserve source-broadcast marks. Do not add scoreboard/team-name blurring as a copyright-avoidance feature; obscuring overlay details does not grant reuse rights. Any future privacy redaction must be narrowly scoped to authorized footage and must not erase source marks.
- YouTube and public Telegram distribution must pass the rights gates in `reelkit.rights`: confirm visual and audio/music rights, source reference, evidence where required, and the chosen destination scope. Unknown rights may be uploaded privately to YouTube for review only; never bypass the gate for public/unlisted/scheduled publishing. Pass `containsSyntheticMedia` when the video includes realistic altered or synthetic content.
- Dashboard auto-publish and Autopilot must load a rights record keyed by the exact source; missing/malformed entries fail closed with no fallback.
- Public/unlisted/scheduled publishing and public Telegram distribution additionally require a structured per-asset registry (`assets`): source, media type, rights holder, permission type/time window, allowed platforms, plus a local evidence file under `rights_evidence/` (or `REEL_RIGHTS_EVIDENCE_DIR`) whose SHA-256 is verified. Asset statuses: `unverified`, `pending_review`, `allowed_within_declared_scope`, `expired`, `rejected`, `out_of_scope`, `not_yet_valid`. The registry records operator declarations; it does not prove ownership or licensing.
- Telegram sending is gated at the library level: `Tg.send_video`/`Tg.send_document` and `TelegramBot.send_video` refuse public sends without a passing rights gate; private previews require a positive numeric user chat id. Autopilot and the dashboard pass the rights record into the sender itself (defense in depth); coverage in `tests/test_telegram_gate.py`.
- Rights records separate visual and audio/music basis and evidence (`visual_rights_basis`, `audio_rights_basis`, `visual_evidence_reference`, `audio_evidence_reference`). Retain fallback to legacy shared fields only when the per-component fields are absent; keep the publish form, reports, templates, docs, and tests aligned.
- Dashboard queue filters are read-only state summaries: `rights_review.form_complete` means the input gate passed, not verified ownership or licensing. They may show missing/incomplete/complete rights forms and YouTube upload states, but must never imply legal clearance or bypass the publish gate.
- In v1.66, `reelkit.errors.friendly_error` returns Arabic remediation messages only — it never echoes raw provider exception text to API responses (secrets/paths can appear in exception strings). `reelkit.errors.error_detail` captures the raw type+message for server-side logs and `reelkit.audit` events only. `dashboard.py` status/publish error paths log `error_detail` and return `friendly_error`. Cover in `tests/test_audit.py` and `tests/test_youtube_dashboard.py`.
- `reelkit.audit.append_event` is the append-only job action trail (JSONL in `audit_log/`, path-traversal safe). Dashboard status/share/publish actions record ok/error/video_id; the log is diagnostics, not a rights record.
