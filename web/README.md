# واجهة elhadath-reels

تحتوي `web/` على واجهتين:

- **واجهة الإنتاج** عند `/app/` — تطبيق React يتصل بمحرك `dashboard.py` الحقيقي.
- **النموذج التجريبي** عند `/app/demo/` — تجربة محلية منفصلة ببيانات تجريبية.

## تشغيل واجهة الإنتاج

تُبنى الملفات مرة واحدة وتُخدّم من لوحة FastAPI؛ لا تحتاج خدمة ويب مستقلة:

```bash
cd web
bun install --frozen-lockfile
bun test
bun run build
cd ..
python dashboard.py
```

افتح رابط الدخول المؤقت الذي تعرضه اللوحة، ثم اختر **واجهة الإنتاج الفعلية** أو افتح `/app/`. الواجهة الجديدة تستخدم جلسة الدخول نفسها وواجهات الخادم، بينما تبقى لوحة HTML الأصلية متاحة في `/`.

للعمل على الواجهة أثناء التطوير، شغّل لوحة التحكم على المنفذ 8000 ثم شغّل `bun run dev` داخل `web/` وافتح `http://127.0.0.1:3000/app/`. يمرر Vite طلبات `/api/` و`/media/` إلى الخادم المحلي. استخدم اسم المضيف نفسه في رابط الدخول وصفحة Vite حتى تصل جلسة المتصفح إلى الطلبات.

## ما تتصل به واجهة الإنتاج

- رفع فيديو إلى مجلد `incoming/` على خادم المشروع باستخدام حد الحجم والتحقق الموجودين في `/api/upload`.
- إنشاء مهمة حقيقية عبر `/api/jobs`، ومراجعة اللقطات عبر جلسة الكشّاف المؤقتة، ومتابعة `/api/jobs` و`/api/queue`.
- إيقاف المهمة وحذفها، ومعاينة الناتج أو تنزيله عبر مسار `/media/` المحمي.
- تبقى المسارات الخام وسجلات التنفيذ خارج واجهة React؛ لا تُحفظ المهام الحقيقية في `LocalStorage`.

لا تنشر هذه الواجهة تلقائياً إلى YouTube أو Telegram. النشر يبقى في اللوحة الحالية وخلف بوابات `reelkit.rights` على الخادم. تُحفظ علامات المصدر افتراضياً، ويعيد الخادم التحقق من نوافذ القص قبل الرندر. الجلسات ومخرجات الوسائط تظل على خادم المشروع.

## دليل سير العمل

تعرض واجهة `/app/` دليلاً من سبع خطوات: اختيار المصدر، مراجعة الحقوق، كشف اللقطات، الرندر، تقرير الجودة، الرفع كخاص، ثم مراجعة YouTube Studio. حالة الكشف والرندر والجودة تُشتق من جلسة الكشّاف ومهام الخادم الفعلية؛ غياب تقرير الجودة لا يعني اجتيازه. الكشف اختياري والرندر المباشر يبقى متاحاً.

مراجعة الحقوق والرفع لا ينفذان من React: الدليل يفتح اللوحة الحالية فقط، ولا يحفظ إقراراً أو يرسل الفيديو. يجب اختيار خصوصية «خاص» والتحقق من القناة يدوياً في اللوحة بعد اجتياز بوابة الحقوق. مراجعة المعالجة والقيود تبقى يدوية في YouTube Studio.

## الجلسة والأمان

- `/app/` وملفاته الثابتة وواجهات API كلها خلف مصادقة اللوحة الحالية؛ لا تضع رمز الدخول في رابط React أو `LocalStorage`.
- يرسل متصفح React الطلبات إلى الأصل نفسه باستخدام ملف جلسة HttpOnly الحالي.
- يعتمد API adapter قائمة حقول للعرض، ويرفض روابط المعاينة التي تخرج عن مسارات الخادم المتوقعة.
- لا يرسل مسار الفيديو أو الملف الكامل إلى Gemini من هذا المسار.

## النموذج التجريبي

تبقى `/app/demo/` متاحة لمراجعة التصميم. وظائف المهام والقنوات والتحليلات والأتمتة والحقوق فيها بيانات محلية نموذجية، وProShot رسم توضيحي لا يتصل بتتبّع YOLO. معاينة Canvas محلية. يمكن لمولّد النص استخدام Gemini بعد موافقة منفصلة لكل توليد؛ مفتاحه الاختياري محفوظ في `sessionStorage` للتبويب، غير مشفّر، ولا ينبغي استخدام هذا النموذج كموقع متعدد المستخدمين.

## الاختبارات والبنية

```bash
bun test
bun run build
```

يتطلب Bun 1.4.4 كما هو مضبوط في CI.

- `src/ProductionApp.tsx` — واجهة الإنتاج المتصلة بالخادم.
- `src/services/dashboardApi.ts` — طلبات same-origin، رفع الملفات، والتحقق من شكل البيانات المعروضة.
- `src/App.tsx` — يختار واجهة الإنتاج أو النموذج التجريبي حسب المسار.
- `src/components/` — مكونات النموذج التجريبي.
- `tests/dashboardApi.test.ts` — اختبارات عزل المسارات ورسائل أخطاء API.
