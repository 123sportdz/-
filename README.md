ياخذ مقطعاً تملك حق استخدامه أو لديك ترخيص له، ويحوّله من **أفقي (16:9)** إلى **ريلز/شورت عمودي 9:16**:

## 1) التثبيت

**المتطلبات:** Python **3.11 – 3.13** (⚠️ 3.14 غير مدعوم من torch)، ffmpeg (يفضّل نسخة فيها `libdav1d`)، ~3-4 GB RAM.
كرت رسومات (GPU) **اختياري** — يشتغل على CPU، بس GPU يسرّع الكشف 10-20 مرة.

### ⚡ الأسرع (عندك uv؟ بلا تنصيب Python إطلاقاً)
```bat
.\bootstrap.bat    :: يجلب Python 3.12 تلقائياً + CUDA + كل المكتبات
.\start.bat
```
```bash
./bootstrap.sh && ./start.sh
```

### ✅ الطريقة الأتوماتيكية (بدون uv)
> ⚠️ في **PowerShell** اكتب `.\` قبل الاسم: `.\install.bat` و `.\start.bat` (أو `cmd /c install.bat`).
```bat
.\install.bat      :: ويندوز: يختار Python المتوافق + ينصّب CUDA تلقائياً لو عندك RTX + يفحص
.\start.bat        :: يشغّل اللوحة (وينصّب/يصلّح تلقائياً لو ناقص)
```
```bash
./install.sh       # لينكس/ماك
./start.sh
```
> 🩺 إذا واجهت أي مشكلة: `python doctor.py --fix` (يصلّح تلقائياً) ثم `python doctor.py --report`.
> ⚠️ شغّل المشروع **دائماً داخل `.venv`** (start.* يفعل ذلك تلقائياً) — تشغيل `doctor.py`
> بمفسّر نظامي قد يُبلغ "مكتبات مفقودة" كذباً.

### 🔧 الطريقة اليدوية
```bash
# 1) ffmpeg  (Ubuntu/Debian)
sudo apt-get update && sudo apt-get install -y ffmpeg

# 2) pytorch — CUDA إن عندك NVIDIA (أسرع 10-20×) وإلا CPU
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121   # RTX
# pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu  # CPU

# 3) باقي المكتبات
pip install -r requirements.txt

# 4) تأكد أن ملف الأوزان موجود: models/ball_detector.pt
```

### 🚀 عندك كرت NVIDIA (مثل RTX 3060)؟ ثبّت نسخة CUDA بدل CPU

```bash
# ألغِ نسخة CPU وثبّت نسخة CUDA 12.1 (مناسبة لـ RTX 3060 + درايفر حديث)
pip uninstall -y torch torchvision
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# المفروض يطبع: True NVIDIA GeForce RTX 3060
```

بعدها **كل شي تلقائي** (v1.42+): الكشف يشتغل على الكرت بـ**FP16 + دفعات (batch 8)**
→ تسريع **10-20×** عن المعالج (فحص 15Hz لمقطع دقيقة: من ~4 دقائق إلى ~20 ثانية).
تتحكم يدوياً بـ `--device 0` و `--batch 8` (أو من ⚙️ الإعدادات في اللوحة).

## 2) الاستخدام الأساسي

```bash
# مقطع هدف كامل
python reel.py -i goal.mp4 -o reel.mp4 --name "الحدث" --url elhadath-dz.com

# مقطع من داخل تسجيل مباراة طويل (قص أول ما يشتغل الكشف)
python reel.py -i full_match.mp4 -o goal.mp4 --start 41:12 --end 41:55 --name "الحدث"

# نسخة سريعة (للاختبار أو جهاز ضعيف) — لا تنزل عن --rate 10 وإلا يضعف كشف الكرة الصغيرة
python reel.py -i goal.mp4 -o reel_fast.mp4 --rate 10 --imgsz 960

# بدون هوية / بدون إزالة واترمارك
python reel.py -i goal.mp4 -o reel.mp4 --no-brand
python reel.py -i goal.mp4 -o reel.mp4 --keep-watermarks
```

### 🎯 محرّك التتبّع الاحترافي (v1.23)

### 🎙️ تحكّم صوت المعلّق

من لوحة **استوديو صوت المعلّق** اختَر أسلوباً جاهزاً (حماسي، جزائري، محلّل، سينمائي أو هادئ)، صوت Edge أو Gemini، ثم استمع إلى معاينة قصيرة قبل الرندر. يمكنك ضبط طول التعليق الذي يكتبه الذكاء الاصطناعي من 8 إلى 80 كلمة (افتراضياً 22)، والحماسة (0–100)، سرعة Edge (-20 إلى +50%)، طبقته (-12 إلى +12 Hz)، مكسب المعلّق، ومستوى صوت الملعب. تفضيلات اللوحة تحفظ محلياً في المتصفح.

- `--commentary-script "..."`: نص يدوي (حتى 500 حرف)؛ يتجاوز كتابة نص التعليق تلقائياً.
- `--commentary-style broadcast|algerian|analyst|cinematic|calm` و`--commentary-energy 0..100`: يتحكمان في كتابة التعليق وGemini TTS.
- `--commentary-words 8..80`: الحد الأعلى لكلمات التعليق الذي يكتبه Gemini؛ الافتراضي 22. لا يغيّر النص اليدوي.

- `--voice-engine auto|gemini|edge` و`--edge-voice ar-DZ-IsmaelNeural` أو `--gemini-voice Fenrir`: اختيار المحرك والصوت.
- `--voice-rate 10` و`--voice-pitch 0`: يخصان Edge؛ 0 يعني السرعة/الطبقة الطبيعية.
- `--voice-gain 1.9` و`--voice-duck 0.22`: مستوى المعلّق وصوت الملعب.
- `--voice-mix auto|fixed|original|voice_only`: خفض ديناميكي أثناء الكلام، خفض ثابت، إبقاء صوت المباراة كاملاً، أو المعلّق فقط.

معاينة اللوحة ترسل الجملة المختارة فقط إلى محرك الصوت، ولا ترسل الفيديو. Gemini يحتاج مفتاحاً محفوظاً في إعدادات المشروع؛ Edge لا يحتاج مفتاح Gemini.

## 3) كيف يشتغل (Pipeline)

1. **تطبيع المصدر** — لو AV1/HEVC (OpenCV ما يفكّها) يحوّل بـffmpeg لـH.264 وسيط، ويطلع الصوت منفصل.
2. **تحليل المشاهد** — يقطع المشاهد (histogram diff) ويحسب **مركز حركة اللاعبين** مع تعويض حركة الكاميرا (phase correlation).
3. **كشف الكرة** — أوزان YOLO مدرّبة على كرة القدم (`models/ball_detector.pt`) بـ`imgsz=1280`، وتُحجب مناطق الواترمارك حتى ما تُفهم غلط.
4. **تتبّع** — Kalman بسرعة ثابتة، **متعدد البذور**، مع `coasting` (يتوقّع المسار لما الكرة تختفي لحظة) ورفض القفزات غير الفيزيائية. كل مشهد يُتتبّع لحاله.
5. **الكاميرا الافتراضية** — الافتراضي يتابع **مركز اللعب** للحفاظ على سياق الهجمة؛ ويمكن اختيار الكرة أو اللاعب. التنعيم وحدود السرعة والتسارع تقلّل اهتزاز القص.
6. **التأطير حسب اللقطة** — لقطة واسعة → **قص متتبّع 9:16**؛ لقطة قريبة (حجم اللاعب > `--pad-thresh`) → **الإطار الكامل وسط خلفية مموّهة**.
7. **حفظ علامات المصدر افتراضياً** — الإزالة خيار يدوي للعلامات التي تملكها أو لديك إذن بإزالتها؛ لا تُستخدم لإخفاء مصدر اللقطة.
8. **الغرافيكس والترميز** — شارة قناتك اختيارية وأعلى الإطار؛ يمكنك إخفاء الاسم مع إبقاء الرابط والشعار. علامات مصدر البث تبقى محفوظة؛ حلقة الكرة ومسارها اختياريان للمراجعة فقط، والتعليق/الكابشن عند تفعيله → H.264 crf20 + الصوت الأصلي.

في الإعدادات اختر إظهار اسم قناتك افتراضياً، أو أوقفه لمقطع واحد؛ يبقى الرابط والشعار كما هما. إخفاء هوية قناتك لا يغيّر حقوق بث المباراة ولا يمنع المطالبات؛ استخدم لقطات تملكها أو لديك ترخيص بنشرها.

في تبويب **🎬 المهام** ابحث وفرز قائمة الرندرات، ثم استخدم فلاتر متابعة الحقوق وYouTube مع أعدادها الحيّة؛ **مسح الفلاتر** يعيد القائمة كاملة. الفلاتر تعرض حالة السجل ولا تمنح إذناً أو تثبت ملكية.

## 4.1) 🤖 التحكّم من هاتفك — بوت تيليجرام (v1.55)

من أي مكان، بلا فتح منافذ ولا IP ثابت ولا port-forwarding — البوت يسأل تيليجرام
بنفسه (**Long Polling**) ثم يقول للوحة على جهازك ماذا تفعل. عملياً: جهازك يبقى
محميّاً خلف الراوتر، وأنت تتحكّم من الجيب.

**الربط (مرّة واحدة)**
```bash
# 1) أنشئ بوتاً: تيليجرام → @BotFather → /newbot → انسخ التوكن
python reelbot.py --setup --token 123456:ABC...
# 2) شغّل
./start_bot.sh          # ويندوز: start_bot.bat
# 3) أرسل للبوت /id ثم اسمح بمحادثتك
python reelbot.py --allow <رقم المعرّف>
```
> الأمان: البوت لا يستجيب إلا لمحدثات القائمة البيضاء (`bot_allowed_chats`) — من
> يصل إليه يستطيع تشغيل مهام على كرتك والنشر على قناتك، فلا تتركها فارغة.

**ماذا تفعل من الهاتف؟**
- 📥 **أرسل رابط مقطع** (t.me/… أو رابطاً مباشراً) أو **ملف فيديو ≤20MB** ← يشغّل المعالجة ويرسل لك الريل جاهزاً في المحادثة.
- 📋 `/jobs` — قائمة المهام الحيّة بأزرار: 🔎 تفاصيل · ⏹ إيقاف · 📤 نشر · 🗑 حذف · 🔁 إعادة.
- 🔭 `/scout <رابط>` — تقرير الكشّاف بلا إنتاج · 🎬 `/quick <رابط>` — معاينة سريعة تُرسل لك الفيديو.
- 🎯 `/goals 3 <رابط> montage` — ثلاثة أهداف من تسجيل طويل + مونتاج.
- 📤 `/publish <id> yt|tg|both` · 🎞️ `/montage <id1,id2,…>` · 📊 `/status` · 💾 `/space`.
- ⚙️ `/settings` و `/set quality high` (أو layout/max_dur/encoder…).
- 🩺 `/doctor` · 🧹 `/clear` (حذف المنتهية) · 🔁 `/retry` (إعادة الفاشلة).

**كيف يشتغل بلا تعارض؟** البوت **واجهة ثانية لنفس المحرّك**: عند الإقلاع يبحث عن
لوحة تعمل على `--port`، فإن لم يجد شغّلها بنفسه، ثم يستدعي واجهتها البرمجية —
فيبقى الطابور و`jobs.json` مصدر حقيقة واحداً (لا انفصال حالة ولا تزاحم على الكرت).

**توكن البوت** يُحفظ في `config.json`، ويمكن تمريره متغير بيئة:
`REEL_BOT_TOKEN`. ولمنع البوت من الإقلاع عند الطلب: `--no-spawn`.

### 🔑 تنزيل فيديوهات تلغرام الكبيرة (v1.32)
تلغرام **لا يعطي رابطاً عاماً** للفيديوهات الكبيرة (`not_supported` / «Media is too big») —

**الحل الجذري:** اربط حسابك في الإعدادات →
`⚙️ الإعدادات → 🔑 تنزيل تيليجرام بحسابك` (api_id/api_hash من my.telegram.org + كود مرّة واحدة):
- تنزيل **أي** فيديو من **أي** قناة عامة (بلا استثناء)

- الجلسة تُخزَّن محلياً في `config.json` (ولا تُرسل لأي مكان)
> بدونه: تُصدر رسالة واضحة تشرح السبب وتطلب تنزيلاً يدوياً (`pip install telethon`).

### 🐞 علّتان خطيرتان أُصلحتا في v1.36 (سبب «ربطت ثم اختفى الربط»)
1. **حفظ الإعدادات كان يمسح الجلسة**: `save_cfg()` كان يكتب من ذاكرة اللوحة فقط فيحذف

2. **الحقول الفاضية كانت تمسح api_hash**: حفظ الإعدادات بقيم فاضية (واجهة تعرض Placeholder)

+ الواجهة صارت تقول: **«البيانات محفوظة ✓ — اضغط QR»** بدل مطالبتك بإعادة كتابتها.

**📱 الربط بمسح QR (v1.34) — الطريقة الموصى بها (بلا كود!):**
`⚙️ الإعدادات → 📱 اعرض رمز QR` → على هاتفك: **تيليجرام → الإعدادات → الأجهزة → ربط جهاز** → امسح.
الرمز يتجدّد تلقائياً (كل 30s) واللوحة تتابع الحالة تلقائياً حتى الربط ✅
(مفيد جداً لما رسالة كود تسجيل الدخول لا تصل — لأنها تحتاج حساباً مسجَّلاً في تطبيق).

**تشخيص «الكود ما يوصل» (v1.33):**
| الأداة | الوظيفة |
|---|---|
| **كيف وصل الكود؟** | بعد الإرسال تقول اللوحة: 📱 داخل تطبيق تلغرام / ✉️ SMS / 📞 مكالمة + عدد الأرقام + مدة الصلاحية |
| **✉️ اطلب الكود برسالة SMS** | يفرض الإرسال كرسالة نصية بدل رسالة التطبيق |
| **🩺 فحص الاتصال** | telethon مثبّت؟ api صحيحة؟ جلسة؟ TCP لسيرفرات تلغرام (3 مراكز)؟ + ملاحظات وحلول |
| **ترجمة الأخطاء** | كل خطأ تلغرام بالعربي مع الحل: ApiIdInvalid · PhoneNumberInvalid · **FloodWait (مع المدة بالضبط)** · PhoneCodeExpired · فشل الاتصال |
| **بروكسي** | `socks5://host:port` أو `http://user:pass@host:port` — لمزوّدي الإنترنت الذين يحجبون MTProto |
| 🔧 إصلاح جوهري | حلقة asyncio **واحدة دائمة** — بدونها كان الربط ينكسر بين «أرسل الكود» و«تأكيد» |

> 🩺 **«عالق على فيديوهات قديمة»؟** الأسباب الثلاثة (كلها مُعالجة):
> 1. تلغرام يخفي روابط الفيديوهات الكبيرة → تُستخرج من صفحة الرسالة ✔
> 2. **تخزين مزوّد الإنترنت** لصفحة t.me/s → كسر كاش تلقائي + طلب `?after=<أحدث id>` ✔
> 3. **لا يوجد جديد فعلاً** (القناة ما نشرت) → اللوحة السابقة كانت تكرّر نفس القائمة بلا توضيح.
>    الآن كل مقطع يُعرض **بتاريخه وعمره** + فلتر «الجديد فقط» + إشعار «ما فيه جديد»
>    + زر **🩺 فحص السبب** الذي يقول لك صراحةً: أحدث رسالة #X بتاريخ Y، وهل فيه تخزين وسيط.
>
> ⚠️ مهم: تلغرام **يخفي رابط الفيديو** من معاينة القناة للفيديوهات الكبيرة
> (`Media is too big` / `not_supported`) — فتظهر فقط الفيديوهات الصغيرة/القديمة.
> المحرّك الآن يستخرج الرابط من **صفحة الرسالة المفردة** تلقائياً، ويأخذ النص من المعاينة
> (لأن الصفحة المفردة تخلط نصوص الرسائل المجاورة) — ولذلك `latest()` يجيب الأحدث فعلاً.
> للفحص: `python doctor.py` → «سحب من @… (أحدث رسالة #3020 | استُخرج 3 فيديو: …)».

## 9) حقوق المحتوى والنشر على YouTube

الأداة لا تستطيع رفعَ حظر حقوقي أو التحايل على Content ID. لا يُعدّ القصّ، أو التعليق الصوتي، أو الإسناد، أو الشعار، أو قِصر المقطع ترخيصاً بحد ذاته ولا يضمن استثناءً قانونياً أو منع المطالبة. احصل على إذن مكتوب يغطي نشر اللقطات والصوت على YouTube وفي البلدان المستهدفة، أو استخدم مواد تملكها.

- تُحفَظ علامات المصدر افتراضياً. `--remove-watermarks` مخصّص فقط لعلامة تملكها أو لديك إذن صريح بإزالتها؛ لا تستخدمه لإخفاء صاحب البث أو مصدر المقطع.
- ارفع أولاً كـ`private`، ثم افحص **YouTube Studio → Content → Restrictions** قبل أي نشر عام. الرفع الخاص لا يمحو المطالبة.
- لفحص حالة الرفع والمعالجة والرفض والقيود الجغرافية من سطر الأوامر: `python -m reelkit.publish.youtube --video-status VIDEO_ID`. تفاصيل Content ID تُراجع في Studio؛ هذا الفحص لا يعرض كل بيانات المطالبات.
- ملف `--rights-package` يسجّل عناصر الإنتاج فقط؛ لا يقيس «fair use»، ولا يثبت الملكية أو الترخيص، ولا ينبغي إرساله كما هو. اعترض فقط إذا كان لديك أساس قانوني حقيقي وأدلة مناسبة.
- الأداة لا تغيّر بصمة المحتوى ولا تحاول الالتفاف على المطالبات؛ تعديل الصورة أو الصوت لتجاوز الكشف قد يعرّض القناة لمزيد من المخاطر.

في اللوحة: كل مهمة مكتملة عندها زر **🛡️ معلومات الإنتاج** (يعرض اكتمال التوثيق فقط، لا صلاحية الاستخدام).

> ⚠️ الملف يسجّل عناصر الإنتاج ولا يثبت الملكية أو الترخيص أو الاستخدام العادل. تحقّق من قيود YouTube Studio، ولا تقدّم اعتراضاً إلا على أساس قانوني صحيح ومدعوم.
